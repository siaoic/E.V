# 游戏回合阶段纪律

打游戏时 AI 同时做三件事：说话（TTS 播报）、做动作（工具调用，改变游戏状态）、生成下一句（模型往返）。三者速度不同：动作毫秒级、生成 2–4 秒、播报 3–6 秒一句。不约束顺序的话，盘面永远跑在嘴前面，观众看到她"操作了但没出声"，非常出戏。本文记录踩过的坑和必须遵守的阶段顺序，写新游戏前先读一遍。

## 抢跑的三种形态（都出现过）

1. **解说整窗延迟**：一个窗口里模型"说一句 → 落一子 → 再说一句"的全部台词攒到窗口结束才一次性交给播报。网页盘面实时在动，声音却在整窗结束后才开始，解说全程落后。
2. **动作抢在话音前**：解说改成逐句交出后，动作仍在 `say` 之后立刻执行——她说"这里填 5"话音未落，数字已经出现在盘面上。
3. **无声动作**：模型一轮里只发工具不说话，盘面无声地变了，观众不知道发生了什么。

## 必须保证的阶段顺序

每一轮（round）严格按下面的顺序走，任何一步都不能提前：

```
说话        say 回调立即交出这句话 → agent/reply → 播报队列 → 观众听到
   ↓
等这句话播完  waitQuiet()：等 unspoken 归零（由 playback/completed 事件回流驱动）
   ↓
做动作      执行工具调用，至多一个"改变游戏状态"的动作；盘面此刻才更新，
            观众刚听完"这里填 5"，数字正好出现
   ↓
回填结果     工具结果写进消息列表，进入下一轮模型生成
```

窗口之间由播报驱动：一句开始播报时若待播队列已空（`waiting === 0`），开下一个窗口。窗口全局串行（`windowRunning`），运行中到达的新请求合并为一个排队窗口，不并发。

## 实现位置

| 机制 | 位置 | 说明 |
| --- | --- | --- |
| `say` 回调 | `src/llm/reply.ts` | 每产出一句话立即交出，不攒批 |
| `waitQuiet` 背压 | `src/llm/plugin.ts` | `unspoken` 计数 + `playback/completed` 回流递减；归零时放行 |
| 守门 `heardPlaybackCompleted` | `src/llm/plugin.ts` | 播报管线从未回流过事件时（单测、无 TTS）跳过等待，避免死等 |
| 一轮一个游戏动作 | `src/llm/reply.ts`（`gameActionDone`） | 同一轮里多个游戏工具调用，只执行第一个，其余返回提示 |
| 游戏窗口轮次上限 | `src/llm/reply.ts`（`GAME_TOOL_ROUNDS = 8`） | 普通窗口 3 轮，游戏窗口 8 轮 |
| 游戏提示词 | 各游戏的 `prompt` 字段 | `reply.ts` 不含任何游戏内容，只负责拼接 |
| 链条自愈 | `src/llm/plugin.ts` | 连续空窗口停摆后由下一个心跳重启；LLM 请求 7 秒超时 |

## 写新游戏的规则清单

1. **引擎纯逻辑、无 IO**（参考 `plugins/10-sudoku` 里数独的 engine 模式——现在位于 `src/games/sudoku/engine.ts`）。错误不自动纠正、不泄露答案——让 AI 自己发现并纠正（用户定的决策：允许错误落盘，自己发现）。
2. **工具层五件套**：`prompt / tools / run / describe / isActive`（参考数独的 tools 模块）。`prompt` 写玩法说明，`describe` 返回给模型看的状态文本，`snapshot()` + `onChange` 供观察页推送。
3. **每轮只做一个改变状态的动作**。`reply.ts` 有硬限制，但工具的 `description` 里也要写明，让模型一开始就不往多动作的方向生成。
4. **动手前先说想法**写进游戏 prompt（"填之前先把心里话说出来"）。这是软约束，靠提示词而不是机器强制；实测若仍出现无声动作，再考虑机器打回。
5. **闲聊腔，不是解说腔**。prompt 里明确禁止报坐标、禁止"我们看到/各位观众"，给口语样例（嘀咕、犹豫、吐槽、得意、后悔）。
6. **网页只显示游戏本身**，页面放游戏文件夹内（`page.ts`），观察服务共用 8787 端口；想换游戏，关掉当前进程再启动下一个。

> 注：原先第 7 条「游戏进行中暂停换话题提示」（`changeTopic` 检查 `game.isActive()`）已随按句数强制换话题一起删除（ADR-0009）——机制不再提示换题，游戏解说自然不会被"换个话题吧"打断。

## 测试的坑

- **messages 数组按引用捕获**：窗口结束后同一数组会被"（这一句必须开口…）"等后续消息原地修改。测试断言消息内容必须在**调用时**快照（把 `messages.at(-1).content` 存进数组），事后读 `mock.calls[i][0].at(-1)` 读到的是被改过的末尾。
- **空窗口是两次模型调用**：模型空回后会被"必须开口"提示重调一次再放弃。数调用次数、配 mock 队列时按 2 次/空窗口算。
- **无播报管线的环境**（单测）`playback/completed` 永远不来，依赖回流的等待必须有 `heardPlaybackCompleted` 这类守卫，否则测试死等超时。
