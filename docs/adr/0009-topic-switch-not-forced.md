# 换话题不由机制强制

Status: 已接受（2026-10-11）

## 决定

删除「按播出句数换话题」这条机制（`TOPIC_SWITCH_EVERY = 8`）：不再在播出 8 句后的下一个窗口提示「你已经聊这个话题有一阵子了，换个新话题吧」，话题池也不再为换题窗口弹出条目。**话题池保留，只在开场窗口弹出一条**；中段聊什么、什么时候换，由她自己决定。

## 理由

1. **机制不规定说什么**。裁决窗口只提供机会，内容由人格与记忆决定；「换个新话题吧」是纯粹的内容指令，属于机制越界。
2. ADR-0002 已经声明「连续发言的人格倾向由宪法种子与话题池承担，**不由机制强制**」。本条只是把这句话落到代码。
3. **没有证据表明她会死磕一个话题**。真机长测（2026-10-10 夜，房间 22748536）里她自己在多个话题间跳转（编程比赛 → 炒鸡蛋 → 刮刮乐 → 蚂蚁搬家），强制换题的收益证据为零，而代价是连贯性被机制打断。
4. 8 这个数没有经验依据；也不需要它来提供多样性——开场话题池、每窗口的记忆召回、`recentSpeech` 与「别重复自己」纪律都还在。

## 如果出现话题死磕（回退方案，现在不做）

不重新引入句数计数，而是用文档里已经定义好的机制：把**话题枯竭度**做成状态水位（事件单位，例如「距上次 A/B 层接话的弹幕条数」「自聊句数」），在事件到达时做阈值评估（`CONTEXT.md` 的「状态跃迁」），跨越时发出内部事件；内部事件只把**素材**交给她（话题池一条 + 记忆联想），措辞是素材不是命令。判定可复用弹幕分层的 A/B 层关键词重合度，不引入新依赖。

验收口径：长测日志里统计「同一话题连续句数」的分布，只有明显长尾（例如出现连续 30 句以上同一话题）才上回退方案。

## 影响

- `src/llm/plugin.ts`：删 `TOPIC_SWITCH_EVERY`、`topicSentences`、`changeTopic`；`topic` 只在 `source === 'start'` 时从池里取。
- `src/llm/reply.ts`：删 `changeTopic` 参数与对应提示文案；开场文案（`可以聊聊：X`）保留。
- 话题池（`LLM_TOPICS` / `config.topics`）语义收窄为「开场素材」。
- 参数表删「换话题间隔（播出句数）8」一行；`src/games/阶段纪律.md` 里「游戏进行中暂停换话题提示」一条随之作废。
