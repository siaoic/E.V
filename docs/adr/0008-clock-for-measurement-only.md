# 时钟只用于度量，不用于输入

Status: 已接受（2026-10-11）

裁决窗口里的**节奏**信息一律以事件单位表达：条数（本次发言后到达了几条弹幕）、句数（已播出几句、连续空窗几次）、心跳数（跨了几个平台心跳），或事件自带的时间戳（弹幕与心跳在解码时已带平台时间戳）。禁止在构建上下文时读取当前时刻、也禁止把「距现在多久」作为裁决输入或开窗依据。

理由：ADR-0001 的零定时器约束除了「不因时间开窗」，还要堵住第二种退化——把时钟读数当作决策数据。一旦模型看到经过时长，实现上就会出现「超过 N 秒没说话就开口」「弹幕超过 N 秒就作废」「冷场满 N 分钟换话题」这类基于时长的规则，等价于把本地时钟重新引入裁决，只是藏进了提示词。而「最新」这件事不需要时钟：缓冲区里的最新一批本身就携带了新鲜度，「距上次发言」也可以由「上次发言后到达了多少条弹幕、跨了几个心跳」完整表达。

时钟仍可用于度量：统一架构文档第 10.1 节的延迟指标（事件投递到上下文构建的耗时、TTFT、单轮往返耗时、工具轮数与耗时、记忆召回耗时、TTS 首音延迟、弹幕到被回复开口的耗时）只写日志与观测，不进上下文、不参与裁决。

绝对日期戳不受本约束：写入笔记与观众档案时打真实日期（`src/memory/persona.ts`、`src/memory/viewers.ts` 用 `new Date().toISOString().slice(0, 10)`），记忆记录的 `createdAt` 作为存储元数据——这些是叙事事实（「这条笔记是 10 月 11 日写的」），不是节奏判断依据。禁止的是**当前时刻与经过时长驱动裁决**，不是记录日期。

与 Cortico 的差异沿用 ADR-0001：它用持久定时器加 DeliveryGate 承担节奏，本系统用事件密度承担节奏。现状符合本约束：`src/llm/plugin.ts` 的停摆恢复按**心跳拍数**计（每 5 拍给一次机会），限流降温同样按心跳拍数计（10 拍），都不读本地时钟、也不用计时器。
