## 1. P0 — 功能性故障

### P0-1 STT 回声防护引用未定义的 `self.cfg`，语音识别结果全部丢失【已验证】

- **位置**：`ev/asr/stt.py:291`（`_deliver` 内）；`ev/asr/stt.py:124`（`__init__(self, cfg)` 从未赋值 `self.cfg`）
- **问题**：
  ```python
  if getattr(self.cfg, "AGENT_TTS_ECHO_GUARD", False) and is_echo_of_recent(text):
  ```
  `getattr` 只兜住「属性不存在」，兜不住 `self.cfg` 本身不存在 → 每次走到这里抛
  `AttributeError`。`_deliver` 经 `call_soon_threadsafe` 在主循环回调中执行，异常被
  asyncio 默认 handler 吞掉，**future 永远不被 set_result，识别文本全部丢失**。
- **症状**：开启 STT 后，日志能看到「流式识别中/转写完成」，stderr 出现
  `AttributeError: 'STTEngine' object has no attribute 'cfg'`，但 AI 永远不回应。
- **现状**：`.env` 当前 `STT_ENABLED=false`，一开就炸。
- **修复**：`__init__` 里加一行 `self.cfg = cfg`。

### P0-2 LLM 错误 / 429 限流全静默，用户侧「说了话但什么都没发生」【已验证】

- **位置**：`ev/llm/brain/chat/inner_loop.py:319-330`（`__ERROR__` / `__RATELIMIT__` 分支仅
  console 打日志后 return）；`ev/llm/utils/constants.py:13`（429 重试总等待封顶 60s）；
  `ev/llm/brain/core.py:33-41`（client `timeout=120, max_retries=2`）
- **问题**：错误链路全程无 TTS、无字幕、无状态提示。唯一有语音反馈的「空响应」兜底
  （inner_loop.py:446-464「我好像卡住了」）覆盖不到错误/限流分支。
- **症状**：说完话 → AI 沉默 0~60s（429）甚至最长 2~4 分钟（超时×重试）→ 然后什么都没有，
  直接回待机。叠加首字延迟 1.9s，是「最像坏掉」的体验。
- **修复**：两个分支各加 `tts.speak` 短提示 + 字幕（「网络开小差了，再问我一次吧~」），
  成本最低收益最大。

### P0-3 RMS 真口型链路 100% 失效，永远走节拍假口型【已验证】

- **位置**：`ev/tts/player.py:92`（回调写死 `cb(None, text, dur_s)`，wav 恒为 None）→
  `ev/kernel/_helpers.py:462-464`（把 None 传给 `load_speech_curve`）→
  `ev/vts/lipsync.py:53,120-128`（`AudioSegment.from_file(None)` 必抛 → 返回 None）
- **问题**：设计中的「解码音频 → 分帧 RMS → 按能量曲线驱动 ParamMouthOpenY」整条链路
  100% 走不到，永远退化为按 `dur_s` 估时长的匀速节拍口型。
- **症状**：嘴匀速规律张合，与音节/停顿完全对不上，长句朗读尤其出戏；
  且 `lipsync.py:127` 的「音频分析失败（可能缺 ffmpeg）」**每句首块误报一次**刷屏。
- **修复**：把合成块的 wav 数据（或临时文件路径）从播放器传进回调；
  `lipsync` 对 None 入参静默跳过、只警告一次。

### P0-4 弹幕卡片 SSE 断线后永久失效，无自动重连

- **位置**：`ui/弹幕卡片v2.html:1692-1696`（`es.onerror` 只 setStatus；重连逻辑被注释删除，
  注释写明「请在浏览器控制台执行 connectSSE()」）；`1716` 仅启动时调用一次
- **症状**：后端重启/断网后弹幕卡永久停止更新，用户必须开控制台手敲命令才能恢复。
- **修复**：恢复 `es.onerror` 里延迟重连（EventSource 关闭后重建），加指数退避。

## 2. P1 — 高频可感知

### P1-1 打断后 LLM 流后台空跑：浪费 token，可拖慢下一轮

- **位置**：`ev/llm/brain/chat/inner_loop.py:277`（drainer 放线程池）；打断链路
  `ev/kernel/handlers/chat.py:114` 的 `conv.cancel()` 只能取消消费协程，**取消不了线程**
- **症状**：被打断后 HTTP 流仍被拉到 `finish_reason`，token 照常计费；僵尸流占满线程池后，
  下一轮对话排队等待 →「AI 突然反应变慢好几秒」。
- **修复**：给 drainer 传取消事件（每 chunk 检查），或关闭底层 HTTP 连接。

### P1-2 打断/出错轮的记忆污染：旧回复配对新输入

- **位置**：`ev/llm/stream.py:244-250`（`on_llm_done` 在 finally 里总触发，取
  `brain.history[-1]` 当本轮回复提交记忆提取）；被打断时 `inner_tail.py:31-76` 不执行
- **症状**：记忆库写入「用户问 A → AI 答了上一轮的 X」错误因果对；长期使用后 AI
  「张冠李戴」。LLM 出错轮（`__ERROR__` 提前 return）同理污染。
- **修复**：`on_llm_done` 增加本轮是否正常完成的标记，异常/打断轮跳过记忆提取。

### P1-3 停顿 0.65s 即切段，且无段间拼接机制

- **位置**：`ev/asr/stt.py:371`（VAD `max_end_silence_time`，.env `STT_SILENCE_SECONDS=0.65`）；
  `stt.py:539-558`（end 立即 `_deliver`）→ `input.py:105-123` 立即返回 → 直接 converse
- **问题**：无「切段后观察窗」、无多段 pending 缓冲；中文口语停顿 0.6~0.8s 常见。
  `STT_MAX_SECONDS=10` 强切的后半段同样变成新输入。
- **症状**：说话稍一停顿 AI 就插话答「半句话」；一句话拆成两轮回复；继续说反而打断 AI。
- **修复**：段间合并窗口（切段后静置 300~500ms 有后续段则合并）；同时评估 0.65→0.8s。

### P1-4 「嗯/啊」等无意义音节直通 LLM

- **位置**：`ev/asr/stt.py:284-302`（只滤空串）；`ev/kernel/handlers/chat.py:98,108-109`、
  `input.py:108-109`（同样只滤空）；对照 `ev/llm/utils/content_check.py` 的
  `has_content()` 只用在输出侧（inner_loop.py:299）
- **症状**：≥0.5s 的语气词触发完整 LLM 请求，AI 郑重作答，浪费 token 与延迟。
- **修复**：把 `has_content()` 复用到输入侧；可选无意义词黑名单（嗯/啊/呃/那个）。

### P1-5 AI 播报期间用户输入被直接丢弃、不排队

- **位置**：`ev/kernel/handlers/input.py:92-95`（键盘）、`111-113`（语音），配合
  `ev/kernel/output_lock.py:59-61` `is_rejecting_input()`
- **症状**：主动发言/弹幕/agent 播报期间用户打字或说话 → 石沉大海，连「稍等」都没有
  →「我说话它不理我」。
- **修复**：改为排队（播报完消费）或至少字幕提示「等我说完哦」。

### P1-6 drain 不等声卡播完：尾段「无声剧」

- **位置**：`ev/tts/engine/core.py:309-324`（drain 只等合成完，注释自述不等声卡）；
  `ev/llm/stream.py:259-273`（drain 返回立刻 `sub.push("clear")` + EV_SPEAKING_END）
- **症状**：回复尾部几秒语音还在念，字幕已清空、表情已复位、状态已 IDLE；
  该窗口内新一轮输入可提前抢占。
- **修复**：按队列剩余音频时长估算 drain 等待（或 AudioQueue 提供播完回调后再收尾）。

### P1-7 TTS 合成异常静默跳句（含 CUDA OOM）；加载期 speak 静默丢弃

- **位置**：`ev/tts/engine/core.py:306-307`（except 一切异常只打暗色小字跳句）；
  `core.py:238-239`（模型未就绪 ~20s 内 speak 直接 return，而字幕依赖音频回调才推）
- **症状**：显存不足/模型报错时 AI「哑巴」但程序不崩、无醒目报错；启动后头 20 秒提问
  既无声音也无字幕。
- **修复**：连续跳句升级为醒目告警 + 用户可见语音/字幕提示；就绪前 speak 改字幕兜底。

### P1-8 字幕页断线无提示、重连后空白

- **位置**：`ui/字幕.html:144-148`（onerror 只做淡出，无状态提示）；
  `ev/utils/subtitle_server.py:213`（`_last_text` 只存不回放）、`133-162`（新连接只发 retry）
- **症状**：网络抖动/休眠唤醒后字幕消失，分不清「说完了」还是「断线了」；重连成功后
  字幕区空白直到下一句。
- **修复**：SSE 新连接补发 `_last_text`；前端加断线/重连角标。

## 6. 验证方法（修复后回归）

```powershell
# 口型链路（P0-3）：说话时观察是否随音节张合（非匀速），
# 且日志不再每句出现「音频分析失败（可能缺 ffmpeg）」

# 错误提示（P0-2）：.env 填错误 LLM_API_KEY 启动 → 说一句话，
# 应在数秒内听到/看到「网络开小差」类提示，而非静默

# 输入过滤（P1-4）：对麦克风说「嗯——」(≥1s) → 不应触发 LLM 回复

# 打断（P1-1/P2-4）：AI 说话时立即插话打断 →
#   a) 后台无继续的流式请求日志（无 token 浪费）
#   b) 不蹦出上一句的半截话
#   c) 打断后连续对话 5 轮，每轮都正常出声

# 字幕（P1-8）：字幕页开着时重启主程序 → 页面显示断线角标，恢复后补发当前字幕

# 记忆（P1-2）：AI 说话中打断 → 查记忆库最新一条，AI 侧内容不应是上一轮旧回复
```
