## 2. 已知问题与约束

- **开场与换题的话题来源单一**：话题池配置已随冷场一起删除，开场和换题只靠模型自己编，因此开场容易收敛到相似的故事（见 3.1 第 1 项）。
- **TTS 截断风险**：`E:\AI\Qwen3-TTS-GGUF\server.py` 的 `max_steps=500` 是单句生成上限，超过会在句中停止，尚未验证它对应多少秒音频。
- **弹幕回复滞后**：句子在播报前生成，弹幕要等当前句播完才会被回应。已通过"只读未读弹幕 + 句子压短"缓解，需要实测确认。
- **WebSocket 关闭握手约 5 秒**：B 站服务器不及时回应关闭帧，Node 在约 5 秒后才发出 `close` 事件。CLI 脚本通过 `process.exit(0)` 绕过；常驻主程序不受影响。
- **所有超时不超过 7 秒**（用户规则，已记入记忆）。长测使用超时参数 `0` 表示挂机，需要手动停止，这是唯一例外。
- **GLM 接入方式**：Coding Plan 地址 `https://open.bigmodel.cn/api/coding/paas/v4`，模型 `glm-5.3-flash`，需设置 `LLM_EXTRA_BODY='{"thinking":{"type":"disabled"}}'`，否则响应超过 7 秒。消息列表必须以 user 结尾（不发用户消息会被 400 code 1214 拒绝），工具结果之后会追加一条 user 消息。
- **账户速率限制**：GLM 返回 `1302 您的账户已达到速率限制` 时，client 会退避重发；重发仍失败则该窗口计为空窗口。
- **TTS 服务需先启动**：`cd E:\AI\Qwen3-TTS-GGUF && PYTHONUTF8=1 TTS_ONNX_PROVIDER=CUDA TTS_VOICE_JSON="voices/灰原哀.json" .venv/Scripts/python.exe server.py`（不带 PYTHONUTF8=1 会因 GBK 控制台下的 emoji 打印崩溃；日志在 `log/latest.log`）。服务是单线程 HTTP，同一时刻只处理一句。
- **TTS 速度实测（RTX 4060 Laptop，2026-10-09）**：模型必须用 `model-base-small`（custom-small 的 ONNX 解码器慢 8 倍）。修复后 RTF 0.35-0.36，首音延迟 0.43s。注意 f16 量化档有采样越界 bug，保持 q5_k+q8_0。
- **话题仍可能跨窗口延续**：新弹幕可能引用旧话题，发言守门只拦截完全相同的句子。
