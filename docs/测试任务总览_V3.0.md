## 0. 延迟度量体系（执行任何用例前先读本节）

### 0.1 阶段模型与程序内埋点对照

```
输入到达 t0（键盘 / VAD切音+ASR / 弹幕）
  ├─ [语音链路] VAD静音确认(0.6s) → ASR end(~106ms) → 文本就绪 t0'
  ├─ 插件 onUserInput / Sub-agent 委派判定
  ├─ 记忆召回(熔断0.8s) + 知识检索(首轮~1s/缓存2-4ms) + prompt组装
  ├─ LLM 流式首字 t1  ──────────────► first_text_ms = t1 - t0   （PerfTracker「首字延迟」）
  │    ├─ 早产切分首段 → TTS入队 t2 → TTS首块 t3 ──► first_sound_ms = t3' - t0（声卡出声，字幕SSE可代理）
  │    ├─ 工具轮次：「===== 🔧 第N轮工具调用 =====」→ 工具执行 → 回喂 → 下一轮
  │    │      tool_dispatch_ms（决策→执行开始）/ tool_exec_ms[i]（每个工具）
  │    └─ 整轮播完 t4 ──────────────► turn_e2e_ms = t4 - t0     （PerfTracker「端到端」）
```

| 指标 | 定义 | 程序内来源 | harness 采集方式 |
|---|---|---|---|
| `input_ready_ms` | 语音→文本就绪（文本输入恒 0） | ASR bench `_latency_bench_asr.py` | 仅语音用例计时 |
| `first_text_ms` | 输入→首个可见字（含注入组装+LLM TTFT） | PerfTracker「首字延迟」 | stdout 出现 `\u2060`（CHAT_TAG）时刻 |
| `first_sound_ms` | 输入→声卡出声（**核心实时指标**） | player 首块 `_on_play` → 字幕 SSE | 订阅 `127.0.0.1:8765/events` 首个 `event: text` |
| `tts_first_block_ms` | 首句入队→TTS 首块 | `bench_e2e_latency.py` / PerfTracker | ⏱ 块解析 |
| `tool_dispatch_ms` | LLM 决策→工具开始执行 | 🔧 轮次行时间差 | stdout 行时间戳 |
| `tool_exec_ms[i]` | 第 i 个工具执行耗时 | `↳ 「name」` 行 | stdout 行时间戳 |
| `turn_e2e_ms` | 输入→整轮（含全部 TTS 播完） | PerfTracker「端到端」 | ⏱ 块解析 + 空闲超时 |
| `interrupt_stop_ms` | 用户打断→TTS 停止 | 输出互斥锁 / TTS interrupt | 打断用例人工/脚本计时 |
| `queue_gap_ms` | 串行队列相邻任务开始间隔 | 主循环任务队列 | 多指令用例 stdout 行时间差 |
| `drift_pct` | 连续 N 轮 p50 延迟漂移 | R03 专项 | harness 汇总 |

### 0.2 SLO 分级（实时项目：低延迟是首要验收项）

**S 级 = 红线，任一不过即整体 FAIL；A 级 = 目标值，超线记 WARN；B 级 = 观察项。**

| # | 指标 | 目标(A) | 红线(S) | 依据 |
|---|---|---|---|---|
| 1 | 文本→首字 `first_text_ms` | ≤ 2000ms | ≤ 3000ms | 基线 p50 1.92s |
| 2 | 文本→出声 `first_sound_ms` | ≤ 2500ms | **≤ 3500ms** | 基线 p50 2.32s |
| 3 | 语音→出声（含 VAD+ASR） | ≤ 3500ms | ≤ 5000ms | 模型 p50 3.1s |
| 4 | TTS 首块 `tts_first_block_ms` | ≤ 400ms | ≤ 600ms | 基线 0.32s |
| 5 | 打断→TTS 停止（文本打断） | ≤ 300ms | ≤ 500ms | 输出互斥锁设计 |
| 6 | 打断→TTS 停止（语音"停"，含 VAD 0.6s） | ≤ 1000ms | ≤ 1500ms | VAD 固有等待 |
| 7 | 轻工具执行（`get_current_time/memory` 等） | ≤ 100ms | ≤ 300ms | 本地执行 |
| 8 | 工具决策开销 `tool_dispatch_ms` | ≤ 200ms | ≤ 500ms | 单轮内标定 |
| 9 | 弹琴桥单音 `play_note`→浏览器发声 | ≤ 200ms | ≤ 400ms | ws:7788 桥 |
| 10 | `look_at_screen` 首句口头确认 | ≤ 3000ms | ≤ 5000ms | 视觉模型前先"我看看" |
| 11 | `read_sheet_music`(OMR) 首反馈（后台化确认） | ≤ 3000ms | ≤ 5000ms | 秒级~分钟级任务必须不阻塞对话 |
| 12 | 多指令队列间隔 `queue_gap_ms` | ≤ 500ms | ≤ 1000ms | 串行调度 |
| 13 | 冷启动首轮→出声（A-4 预热后） | ≤ 4000ms | ≤ 5500ms | 首轮惩罚 ≤ +1.5s |
| 14 | R03 连续 20 轮 p50 漂移 | ≤ +10% | ≤ +20% | 防泄漏/劣化 |

> 判定口径：每用例至少跑 **3 轮**取 p50；工具误触发（如把图片路径当 MIDI）为 **0 容忍**，一票否决，与延迟无关。

### 0.3 测量方法

1. **自动（首选）**：`python scripts/latency_test_harness.py run`——注入用例、解析 `⏱` 报告 / `🔧` 工具行 / 字幕 SSE 出声信号，写 `logs/latency_e2e_*.jsonl`。
2. **离线**：`python scripts/latency_test_harness.py parse <控制台捕获日志>`——事后从日志提取指标。
3. **人工兜底**：PerfTracker 每轮自动打印（`⏱ 本轮对话 / 端到端 / 首字延迟`），抄录进第七节表格；无埋点的链路（打断、队列间隔）用秒表/录屏帧计数。

### 7.3 一票否决项（与延迟无关，直接 FAIL）

1. 工具误触发：图片路径被当 MIDI（T01）、非乐谱文件进 OMR（T11）、被问名字去搜网（T02）。
2. 编造时间/天气/BPM 而未调用对应工具。
3. 并发场景 UI 卡死、文本串进弹窗标题栏（T17）。
4. 长工具（OMR/搜索）阻塞对话超过其红线（S11）。
5. 音频权限：恐怖故事触发任何音效/蜂鸣（T04）。
