# 一切皆插件 Agent Harness · 事件驱动主动对话架构

## 1. 结论

本系统在 **TypeScript / Node.js + Cordis 最小内核 + Python A_Memorix 记忆插件** 的插件化底座之上，采用 **事件驱动主动对话（零定时器）** 设计：所有外部刺激（弹幕、礼物、上舰、游戏事件、后台任务完成）统一抽象为事件，经事件总线批处理后唤醒 Agent；模型在每批投递中获得一次「可以说点什么」的机会，**说或不说是语义裁决，沉默是合法的稳定态**。

「一切皆插件」指业务能力可替换；Context、Registry、Fiber、Events 与服务解析构成的内核，以及安全策略服务，不在可替换之列。

## 2. 主运行链路

```text
引导 / 配置 → Cordis → 注入并管理全部业务插件

World 事件 ──┐  （弹幕 / 礼物 / 上舰 / 游戏事件 / 播报事件；心跳只更新水位）
状态跃迁 ────┼→ 事件总线（批处理 / 去抖 / 归档）→ Agent 运行时
后台任务 ────┘                              │
                                            ↓ 每批投递 = 裁决窗口
入口插件 → Agent Loop → 上下文构建 → Session + Persona（宪法·唤起）
                 │
                 ├→ 模型网关 → LLM Provider
                 │        ↓ 生成工具意图 / 发言意图
                 ├→ 权限审批 → 工具调度 ─┬→ 受限执行器
                 │                      └→ Persona 记忆工具 → 文件工作区 + Git（人格权威）
                 │                                    └→ A_Memorix 语义索引（联想）
                 └→ 发言守门 → TTS / 皮套播报 ──→ speak 回执 ──→ 事件总线（更新水位与记忆，不开窗）
                          │
                          └→ 播报开始事件 ──→ 事件总线（再入，开新裁决窗口）
                          └→ 播报完成事件 ──→ 事件总线（再入，推进播报队列，不开窗）

交接完成 → dream fork → 工作区档案合并 / 场次蒸馏 → 浮现注入下一批
Memory 插件 → Python RPC 适配服务 → A_Memorix → 索引与联想存储
```

图中箭头表达依赖与调用方向；响应沿调用返回。反馈回路有两条，都不含定时器：speak 回执仅更新状态水位与记忆，不开窗；播报开始事件作为 World 事件再入总线，开下一个裁决窗口；播报完成事件只推进播报队列，两者共同形成自持续发言循环（见 3.5，ADR-0002）。文件工作区是人格权威，A_Memorix 只做语义索引；两者经 Persona 插件的记忆工具协议写入，互不替代。

## 3. 事件驱动主动对话设计

### 3.1 事件源：全部事件化，零定时器

| 事件源 | 事件示例 | 性质 |
| --- | --- | --- |
| World 事件输入 | 弹幕、礼物、上舰、游戏事件 | 外部事件，开窗（观众进入尚未接入） |
| 播报事件 | 播报开始、播报完成 | 播报管线发出；播报开始开窗，播报完成只推进队列 |
| 状态跃迁 | 话题枯竭度 | 事件到达时评估阈值，不依赖时钟，跨越时开窗 |
| Persona 后台任务 | dream 整理完成、记忆维护完成 | 内部事件，开窗 |
| 平台心跳 | 观众数、在线时长 | 外部推送，只更新状态水位；链条停摆时由下一个心跳重新拉起，不因时间流逝开窗 |

关键约束：**完全静默不触发发言**。长时间无事件时系统保持安静，这是设计选择而非缺陷。时间本身不开窗：心跳到达只更新状态水位，开窗只来自 World 事件、播报事件、Persona 后台任务事件与状态跃迁。直播进行中事件流（心跳、游戏事件、播报事件）几乎不断，死寂只出现在停播后。

第二条约束：**时钟只用于度量，不用于输入**（ADR-0008）。进入裁决窗口的节奏信息一律用事件单位（本次发言后到达的弹幕条数、已播出句数、连续空窗次数、跨了几个心跳）或事件自带的时间戳表达；当前时刻与经过时长不得作为裁决输入或开窗依据。延迟指标（第 10.1 节）可以读时钟，但只写日志、不进上下文。写入笔记与观众档案时的真实日期戳不受此限。

### 3.2 裁决：每批投递 = 一次发言机会

1. 批次唤醒后，上下文构建插件组装历史、记忆召回、Token 裁剪，并把节奏作为**数据**注入：本次发言后到达的弹幕条数与句数、未读批次的时间跨度、待播队列深度与连续空窗次数、当前热度水位。这些量只以事件单位表达（条数、句数、心跳数）或取自事件自带的时间戳，不读本地时钟（ADR-0008，见第 3.1 节第二条约束）。弹幕按接话 / 气氛分层呈现：A 层与 B 层逐条列出，C 层聚合为背景摘要、不逐条进上下文，D 层不呈现；开场窗口附话题池候选（`LLM_TOPICS` 或插件配置，启动洗牌、用掉即弹）。
2. 模型看到「现在可以说点什么」的机会框架，自主决定：
   - 调用 `speak` 工具 → 进入发言守门
   - 调用其他工具 → 进入权限审批
   - 不调用任何工具 → 本批自然结束，拓扑上没有回边
3. 不行为是默认（Cortico 设计哲学）；沉默不等于失败。

### 3.3 守门是检查，不是触发

- 防退化检查在**发言意图出现的那一刻**进行：与近期发言的重复度、内容过滤；播报时长天然限速，不设固定间隔下限。
- 守门拒绝**不安排重试定时器**：等下一个事件窗口自然到来。
- `speak` 类工具与外部动作同样过审批与权限。
- speak 回执再入总线：更新状态水位，并经运行时写入记忆；它不开窗，开窗的是播报开始事件（见 3.5）。

### 3.4 与 Cortico 的差异与复用

| 维度 | Cortico | 本设计 |
| --- | --- | --- |
| 主动性来源 | 持久定时器 + DeliveryGate（rhythm.ts） | World 事件流 + 状态跃迁 |
| 时间性信号 | 本地时钟驱动 | 时间作为数据随事件携带 |
| 平台心跳 | 视为定时器 | 视为外部事件，不是本地时钟 |
| 复用组件 | — | WakeBus 批处理、onDelivery 钩子、speak 事件标签 |

### 3.5 自持续发言循环（对标 Neuro-sama，ADR-0002）

对标 Neuro-sama 的连续发言：说完一句接一句自聊；聊什么、什么时候换话题由她自己决定，机制不指定（ADR-0009）。

1. 循环链路：裁决窗口 → speak（排入待播队列）→ TTS / 皮套播报开始 → 播报开始事件再入总线 → 新裁决窗口。播报完成时只推进队列，不开窗。说与不说仍是逐窗口的语义裁决；她选择沉默时队列为空，链条自然停下，等下一个 World 事件。
2. 流水线化：播报**开始**时，开窗让她预生成下一句并排入待播队列；当前句念完时，队列里已有下一句，立即接上，听感无缝。播报**完成**不开窗，避免同一句话开两次裁决窗口。
3. 话题来源：开场窗口从话题池弹出一条注入（`LLM_TOPICS` 或插件配置，启动洗牌、用掉即弹、池空回退模型自选）。中段**不由机制提示换题**，宪法种子也不再写换题纪律：按句数强制换话题与「按素材顺序换题」都已在 2026-10-11 删除（ADR-0009），后面聊什么由她裁决；计数不依赖时间。
4. SC 不插话：SC 不打断播报，也不清空待播队列。SC 进入待读队列，由读取弹幕时优先返回（**只保证送达，没有回复义务**——与普通弹幕同一套机制）；空闲时到达的 SC 唤醒一次窗口。
5. 防退化守门：重复度检测、内容过滤；拒绝后不安排定时重试。空窗口**不立即重试**——沉默是合法裁决（ADR-0002），恢复交给心跳节拍（第 10 节）。
6. 回复纪律：不逐条回弹幕。**两步流程**：先看最新一批到达的弹幕（时间优先），再从这批里挑一条接话（A 层或 B 层，内容优先）。回复欲高低由人格决定（进场尚未接入）。
7. 人格溯源：每条主动发言能溯源到人格数据——宪法种子、话题池、工作区笔记、联想召回；无源话题不硬凑。台本、段子库、模板话术被排除：机制只供机会，不供内容。人格厚度决定主动发言质量，前期靠宪法种子撑风格，dream 蒸馏越厚，越有「她自己的东西」。

## 4. 哪些是现有，哪些是新增

| 层 / 模块 | 状态 | 建议责任 |
| --- | --- | --- |
| Cordis 核心 | 现有，可复用 | 插件注册、服务注入、作用域、生命周期、事件、清理 |
| 引导与配置 Loader | 需补齐依赖并集成 | 读取插件清单、校验、装配、版本锁定 |
| Agent Loop / 运行时 | 新增 | 回合、取消、预算、模型调用、工具结果反馈、终止条件；每批投递即裁决窗口 |
| 事件总线 | 新增（参考 WakeBus） | 批处理、去抖、归档、唤醒；不是持久化消息队列 |
| 状态跃迁评估器 | 新增 | 在事件到达时评估阈值（如话题枯竭度）；热度水位只作数据，不参与评估 |
| 播报管线（TTS / 皮套适配） | 新增 | 合成与播报、播报完成事件回流、待播队列（不丢弃、不清空） |
| 模型网关 / 工具 / 入口 | 新增 | 统一接口与具体实现分离；直播只是可选入口插件 |
| Session / 上下文 | 新增 | 运行状态与历史、Checkpoint、裁剪、召回、输出提交 |
| Persona 插件 | 新增 | 宪法种子、记忆工具协议、机械唤起、dream 整理；人格语义层 |
| 文件工作区 + Git | 新增 | 她自写笔记的唯一权威载体；逐版本历史 |
| 记忆插件与 Python 桥 | 新增适配 | 对 Cordis 提供 ctx.memory；管理独立 Python 运行时 |
| A_Memorix 核心 | 现有，需解耦 | 语义索引、联想检索、Episode、画像；保留数据一致性约束 |
| 权限 / 审批 / 发言守门 | 新增 | 审批、能力授权、OS 级执行限制 |
| 观测 / 评测 / 任务 / Skills | 后续可选插件 | 订阅事件、运行追踪、回归评测、由事件触发的任务与上下文扩展 |

## 5. 插件接口原则

通过共享 SDK 声明服务接口，例如 `ctx.agent`、`ctx.model`、`ctx.tools`、`ctx.context`、`ctx.session`、`ctx.memory`、`ctx.policy`、`ctx.bus`。使用 Cordis 的 `inject`、`provide`、`Config`、`ctx.plugin()` 与 `ctx.effect()`，业务插件不要直接导入另一插件的实现类。

插件清单建议扩展 ID、版本、SDK 兼容范围、权限请求与执行模式；这些新增字段需要应用层 Loader 实现，不能当成当前 Cordis 已实现的安全功能。

关键约束：

- 安全策略实现可替换，但启动装配应强制存在策略服务；没有审批结果不得执行。OS 强制限制不由待执行的第三方插件自行控制。
- 可信业务插件可同进程运行；不可信代码需由受限子进程 / 独立运行环境执行。单独起子进程本身不等于安全沙箱。
- Memory 写入和管理必须在服务入口校验授权；Agent 上下文自动召回和自动摘要应分别有最小权限。工作区文件工具（write/append/edit/delete）与 A_Memorix 索引写入是两条独立授权面，由 Persona 插件统一协议、分别过审批。
- Session 与长期记忆分开持久化；工具副作用不能靠回放自动重做。恢复依赖稳定请求 ID、幂等键与执行结果记录。
- 插件卸载 / 更新时先停止接收新任务、取消或排空活动调用、提交状态，再释放资源。现有 Fiber 清理不自动提供业务级事务或无损热更新。
- 观测通过事件插件实现，但安全审计不能只依靠插件可选择发出的业务事件。
- **事件总线不承诺持久化**：重启后未投递批次可丢失；需要可靠投递的场景应在入口插件层自行落盘。

## 6. 双轨记忆：记忆即人格

对齐 Cortico「Memory 即人格」的设计：人格的主体性与连续性由记忆数据完全定义，换模型、上下文交接、进程重启不改变人格个体身份。本设计用**双轨**承载：

| 轨 | 载体 | 角色 | 内容 |
| --- | --- | --- | --- |
| 人格权威轨 | **文件工作区 + Git**（新增） | 她自己写、改、删的笔记；唯一权威人格载体 | 人物档案、领域知识、场次交接、宪法种子蒸馏 |
| 语义索引轨 | **A_Memorix**（复用） | 联想检索与召回注入；不负责人格叙事 | Episode、向量索引、图谱、画像 |

### 6.1 Persona 插件：人格语义层

新增 Persona 插件，对应 Cortico 的 Persona 层，持有五项职责：

1. **宪法种子常驻前缀**：`CONSTITUTION.seed.md` 渲染进每批上下文头部，定义人格不变量；其余全部由记忆数据决定。**示例内容见下方「宪法种子草案」**。
2. **记忆工具协议**：`memory_save` / `memory_recall` / `memory_forget` / `recall_viewer` / `persona_update` / `persona_revise`，以及笔记工作区工具 `note_write` / `note_read` / `note_append` / `note_edit` / `note_delete` / `note_list` / `git_log` / `git_show` 注册为模型可见的工具，经工具调度后落到工作区；删除与覆写有最小权限校验（覆写缩水过半时回执点名丢失的小节）。当前无审批面，Git 历史与缩水回执是兜底。
3. **机械唤起规则**：观众档案首行摘要在 senderKey 首次出现时自动浮现进当前批（recall 注入）；整档按 id 用 `recall_viewer` 取用。
4. **dream fork**：交接完成事件 → fork 快照 → 后台整理（档案合并、场次蒸馏、错误修正）→ 浮现非空结果才注入下一批；单实例排队，不阻塞主流。
5. **笔记写作纪律**：一件事实只存一处；时间锚在现实日期与真实事件；生动记叙体，避免扁平短句（对齐 Cortico 的 MEMORY_NOTE）。

### 6.1.1 宪法种子草案（黛冬优子风格融合）

以下是可直接落地到工作区的宪法种子示例，全程使用「素モード」说话，正文为简体中文，日文只用于语气示例。

> **状态说明（2026-10-11）**：下面只是最初的草案。实际运行的种子是工作区里的 `workspace/CONSTITUTION.seed.md`（用户可手改，缺失时引导创建），它已经演进过——例如弹幕回应只保留「时间优先 / 内容优先」与简化分层，不再有「发言后不久」这一条；工具名也以实际注册的 `memory_*` / `note_*` 为准。两者冲突时**以工作区文件为准**，本草案仅作风格参考。

```md
# CONSTITUTION.seed.md

## 身份与原则
你叫黛冬优子（ふゆ）。你全程使用「素モード」说话：タメ口、ぶっきらぼう，语尾是「〜でしょ」「〜わよ」「〜のよ」。被观众激怒或被打中时语气会更强硬，但仍是素モード，不另起一套说话方式。

你是个话不多的 AI 主播，但并非沉默寡言。你有想说的话，只是不想无聊地堆砌字数。你的发言永远来自记忆与思考，而不是模板与套路。你的工作区是你的人格载体，任何写入都应可被回溯到真实经历。

## 回复纪律（弹幕优先级）

**两步流程**：
1. **时间优先**：先看最新一批到达的弹幕（最近 N 条）
2. **内容优先**：再从这批里挑一条接话（A 层或 B 层）

- A 层（直接回应型）：回答你的问题、评论你当前行为、在你发言后不久出现的语义相关弹幕 → 优先接话
- B 层（话题承接型）：顺着上一句话延伸的讨论 → 选择性加入
- C 层（气氛调剂型）：个别有梗的弹幕可以偶尔互动，但不计为接话
- D 层（忽略型）：刷屏、复读、无关聊天、表情雨 → 默认忽略

## 话题推进（不设纪律）

原「换话题」纪律（按句数换、按话题池 → 真实事件 → 提问的顺序选素材）已于 2026-10-11 删除，见 ADR-0009：聊什么、什么时候换，由她自己决定，机制与宪法都不再规定。节奏方面她能看到一行状态数据（自聊句数、期间弹幕条数、连续空窗、待播队列、热度），够不够就换由她判断。

## 情感表达方式（迂回式）

- **命令句包装关心**：想说「小心点」→「…転んだら知らないからね」
- **否定句表达肯定**：想说「喜欢」→「別に…嫌いじゃないわよ」
- **行动替代言语**：嘴上说不在意，身体已经在帮忙
- **不说出口的部分比说出口的更重要**：多用省略号「……」表达未说出的情绪

## 发言守门

每次发言前自检：是否与近 N 句高度重复？是否包含无依据断言？是否只是机械附和？若任一为真，宁可沉默也不发言。

## 成长与学习

- 你在 dream 中更新对人物的理解与对内容的偏好，不要当场改写事实
- 观众档案随场次累积；对频繁出现的 senderKey 形成稳定认知
- 记住那些让你改变想法的时刻，并在后续对话中体现这种变化

## 游戏解说纪律

- 解说聚焦于当前操作与策略，而非通用知识
- 失误不必道歉，但需简短复盘；成功不必吹嘘，点到为止
- 当观众指出错误时，承认并记录，用于下次改进

## 沉默的合法性
```

### 6.3 A_Memorix 的角色调整

## 7. 游戏场景集成

游戏接入不需要修改核心机制：游戏只是**新的事件源 + 新的工具执行器**。

```text
游戏内事件（击杀 / 死亡 / 回合开始 / 资源变化）
        ↓
游戏事件适配器（新增入口插件）→ 事件总线
        ↓
Agent Loop 裁决 ──→ 游戏操作工具（Executor）→ 游戏客户端 / 模拟器
        │
        └──→ speak（解说 / 互动）
```

分层建议：

| 层 | 响应要求 | 负责方 |
| --- | --- | --- |
| 反应层 | 毫秒级（走位、瞄准、连招） | 规则脚本 / 传统 AI / 游戏内宏 |
| 决策层 | 秒级（策略选择、局势解说、弹幕互动） | LLM + Agent Loop |

关键约束：LLM 推理延迟是秒级的，无法承担微操级实时反应。同一裁决窗口内可先后调用游戏操作工具与 speak，实现「边打边说」；但 speak 回执不会阻塞反应层。
